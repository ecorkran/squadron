Install and verify

uv tool install squadron-ai
sq setup
sq doctor -v
sq auth status
sq models list
  • uv tool install installs Squadron.
  • sq setup configures integrations and providers.
  • sq doctor -v checks setup and prints fix hints.
  • sq auth status shows provider sign-in state.
  • sq models list lists model aliases you can use.

Run one focused review

sq review arch path/to/architecture.md -v --model <alias>
sq review slice 175 -v --model <alias>
sq review tasks 175 -v --model <alias>
sq review code 175 -v --model <alias>
  • review arch checks an architecture document.
  • review slice checks a slice design.
  • review tasks checks a slice task breakdown.
  • review code checks implementation changes.
  • -v shows full findings; --model selects an alias.

A slice number lets SQ resolve registered artifacts through CF; explicit paths also work.

sq review resolve 175 -v --model <alias>

After fixing findings, resolve records whether they were addressed without rewriting the original review.

Pipelines are recipes, not magic

A pipeline is a named sequence of steps. Depending on its recipe, it can ask models to create or edit files, run reviews, revise from feedback, commit, summarize, or stop for a person at a checkpoint.

P4

Design one slice, review the design, then revise against feedback until accepted or a checkpoint is needed.

P456

Chain slice design, task breakdown, implementation, and devlog. This larger workflow can make many file changes.

sq pipelines list
sq pipelines show P4
sq run P4 175 --dry-run
sq run P4 175
sq runs list
  • pipelines list shows available recipes.
  • pipelines show P4 displays a recipe’s steps.
  • run P4 175 --dry-run previews the planned run.
  • run P4 175 executes it; steps may write files.
  • runs list finds active, paused, or failed runs.
Before running: confirm project and slice; inspect file writes, shell commands, and commits. --dry-run previews the plan but does not make execution read-only.

Create your own pipeline

Create project-documents/user/pipelines/my-design.yaml in the project. Start from the annotated reference: sq pipelines show example (add --path to locate its YAML). A pipeline is ordered YAML: description and steps are required; params and a default model are optional.

description: Design and review one slice
params:
  slice: required
  model: sonnet
steps:
  - design:
      phase: 4
      model: "{model}"
      review: { template: slice }
      checkpoint: on-concerns

slice: required becomes the target argument; model: sonnet is a default. Steps run in order. Quote placeholders when they are the entire YAML value: model: "{model}".

sq run my-design --validate
sq run my-design 175 --dry-run
sq run my-design 175

Validation checks the YAML and step configuration; dry-run previews the resolved plan; the last command executes it. Project pipelines are searched first, then ~/.config/squadron/pipelines/, then built-ins. Reuse a name to override; choose a new name to keep both.
