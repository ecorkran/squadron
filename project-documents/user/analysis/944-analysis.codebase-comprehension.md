## 5. Suggested reading order

From `tour[]` (`order`, `title`, `description`), in `order` ascending. 15 steps.

1. **Packaging and CLI Assembly** — `squadron-ai` presents as one command, `sq`. The pyproject manifest binds it to `squadron.cli.app:app`; that root has the highest fan-out in the codebase (22 outgoing edges), making it the best available map of what squadron can do.
2. **The `sq review` Command** — `cli/commands/review.py` implements `slice`, `arch`, `tasks`, `code`, `list`, and `resolve`, and is the fourth-highest fan-out file because one review pulls in templates, models, rules, and diff inputs.
3. **Executing a Review** — `review_client.py` builds the prompt and routes through the provider registry's Agent interface; `git_utils.py` resolves what a slice diff means and `rules.py` folds matching rules into the prompt.
4. **Templates: Reviews as Data** — the central design decision: a review type is a YAML file, not a code path. `code.yaml` shows the escape hatch, naming a dotted Python path when a prompt needs real logic.
5. **Parsing the Verdict** — `parsers.py` extracts verdict, score, criteria, and findings, and validates that each finding's claimed location exists, so a hallucinated line reference does not survive.
6. **Did the Findings Get Fixed?** — `review/addressed/`; `verification.py` downgrades unsupported judge claims to "disputed" so the verdict derives from evidence, and `screens.py` settles byte-identical rounds with no model call.
7. **Pipelines: Reviews Become Workflows** — `loader.py`, `schema.py`, and `models.py` (36 incoming edges, second-most depended-upon module).
8. **The Execution Engine** — `executor.py` walks a PipelineDefinition handling retries, fan-out, and checkpoints; `state.py` persists run state with atomic write-then-rename so a paused run survives.
9. **Extensibility: Steps and Actions** — two parallel Protocol-plus-registry pairs instead of a switch over step kinds. Adding a type means writing and registering a class, never editing the executor.
10. **The Findings-Addressed Gate** — deterministic screens sequenced before the paid judge leg; `evidence.py` is deliberately named outside the `*-review.*` namespace so metrology never mistakes it for a calibration sample.
11. **The Provider Abstraction** — `providers/base.py` (16 incoming edges) declares Protocols, no base classes; `loader.py` imports lazily so unused SDKs never get imported.
12. **Events and Side Effects** — a closed EventType enum and one dispatcher with deliberately different reduction semantics per event kind (all failures for COMMIT, first failure for POST_ACTION).
13. **Metrology: Measuring the Runs** — `store.py`, `audit.py`, `calibration.py`, and `graduation.py` turn accumulated samples into judgments about whether a configuration is trustworthy.
14. **Shared Foundation** — `logging.py` has 70 incoming edges, nearly a third of the graph, which is why failures come out in a uniform greppable shape.
15. **The Daemon Surface** — `server/app.py`, `engine.py`, `daemon.py`, and `client/http.py`, reached by `sq serve`.

The tour's order matches the layer sizes in section 2: it opens on the CLI, spends steps 7–10 in Pipeline Orchestration, and closes on the daemon.
