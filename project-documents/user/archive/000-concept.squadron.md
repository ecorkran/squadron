## Overview

Squadron runs repeatable AI workflows from the terminal: structured reviews, YAML-defined pipelines,
and generated project artifacts, against whatever model you choose. Its README leads with that
framing — "Repeatable AI workflows from the terminal — structured reviews, YAML pipelines, and
project artifacts, using whatever model you want."

Reviews are the most developed surface: `sq review` executes a YAML template against a diff, design
document, or task plan and returns a verdict (PASS, CONCERNS, or FAIL) with severity-tagged
findings. Pipelines generalize that into multi-step runs — and specifically **drive the
context-forge state machine**, rather than orchestrating agents in the abstract. The **server
surface is expected to move to amoeba**; it is present in this codebase today but is not where
squadron's future work is aimed.

## Refined Concept

### Problem & Motivation

From `README.md`. Squadron addresses the gap between ad-hoc LLM prompting and repeatable
engineering process. A review typed by hand into a chat window produces a different shape of answer
every time; squadron runs the same purpose-built template every time and returns a structured
verdict plus findings with severity levels, so results are comparable across runs and across
models. The README states the mechanism directly: "Each review runs against a purpose-built
template that tells the agent exactly what to evaluate and how to report it: a verdict (PASS,
CONCERNS, or FAIL) plus findings with severity levels. Same template, structurally consistent
output, every run."

The second problem is composition. Individual reviews are useful, but the work they belong to spans
steps — review, address findings, regenerate an artifact, review again. The README describes
pipelines as the answer: "Define a pipeline in YAML and it chains reviews, artifact generation,
judges, and loops into one repeatable command."

**Engagement context.** The immediate motivation for this analysis is a **maintenance takeover and
modernization** of the existing codebase — not a greenfield build. That framing sets the near-term
priority: understand what is here, keep it working, and modernize deliberately rather than
rewriting.

### Target Users

From `README.md` and the graph's entry surfaces. Squadron targets developers running structured AI
workflows on their own projects from a terminal — the README's opening example is `sq review slice
120 -v`, a single command against a project artifact.

Access is primarily the **CLI**: the graph's CLI Surface layer holds a Typer application root plus
27 `sq` sub-commands covering reviews, pipeline runs, auth, metrology, and skills. Of the 28
file-level nodes tagged `entry-point`, most sit under `src/squadron/cli/`, with `pyproject.toml`
carrying the console-script definition that makes `sq` reachable after install.

Two further access paths exist in `project.frameworks`: an **MCP** surface and a **FastAPI**
daemon, which let external processes drive squadron over HTTP/IPC rather than the terminal. Per the
Overview correction, that server surface is expected to become amoeba's responsibility.

### Initial Technical Direction
